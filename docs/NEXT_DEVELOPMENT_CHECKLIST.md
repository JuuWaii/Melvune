## 本轮范围与交付

目标：**0.2.0-rc.2，Windows x64 桌面播放联动候选版**。共用现有播放器，实现以下三个互相关联的需求，再统一集成、回归和交付。

1. **Windows 媒体信息和媒体键**：系统可显示当前歌曲、歌手、专辑、封面及播放状态；播放/暂停、上一首/下一首和支持的定位命令进入现有播放队列与定位链路。
2. **独立桌面歌词**：应用外的歌词窗口，可显示/隐藏、拖动、置顶、锁定、调节字号，并保存位置和显示偏好。与应用内歌词共用解析结果和实际播放位置，兼容有时间轴、纯文本、无歌词及歌词加载中状态。
3. **本机音乐/歌词信息接口**：提供当前用户可发现的只读 NamedPipe JSON 协议和独立示例客户端，读取当前歌曲、播放状态、实际位置和歌词。接口默认关闭；第三方软件需按协议接入，不承诺任何软件自动兼容。

交付便携 ZIP、便携 EXE、安装 EXE、MSI、SHA-256、使用指南、协议说明和一页用户验证单。**本轮先交付本地产物和发布材料**；新的 GitHub 上传/标签推送另按用户授权执行。

## 批次、并行与检查规则

### A：统一数据基础，并行开发三项功能（N02–N05）

主代理先定义播放快照、事件和命令契约，再将 SMTC、桌面歌词、本机协议分别交给子代理。子代理可以编写针对性回归，但不各自重复运行整套构建、窗口测试或打包。

| 负责人 | 独立实现范围 | 合并约束 |
| --- | --- | --- |
| 主代理 | 共用快照、主窗口/播放层接线、封面字节提取、公共设置模型、版本/打包与清单 | 共享文件由主代理统一修改，避免并行冲突 |
| 子代理 A | Windows 媒体桥接服务及独立回归 | 通过约定的快照和命令连接，不另建播放器 |
| 子代理 B | 桌面歌词窗口及独立设置/回归 | 接收快照和主题，不直接修改现有应用内歌词布局 |
| 子代理 C | 只读协议、NamedPipe 服务、发现和独立消费者/回归 | 核心模型无 WinUI 依赖，不读取或输出账号/服务私有信息 |

若受可用代理数量限制，主代理先完成公共基础，再调度独立模块，不开启第二个竞争修改本仓库的长任务。

### B：整合设置、退出恢复和交付资料（N06–N07）

三个功能完成后统一接线。检查晚到的封面/歌词、账号切换和本地播放保留、实例隔离、退出释放、配置兼容及设置启停行为。保持现有应用内歌词、队列、主题、库和歌单行为。

### C：集中检查、打包和交付（N08–N11）

先进行一轮源码集中检查，修复后打包，再用最终包集中验收。**不每修改一个控件就重跑全套，不重复扩大旧格式/账号/规模矩阵**。失败先定位原因，仅重跑受影响项目；新实质改动或未解决风险才触发补充完整检查。

关键回归覆盖：播放/暂停/定位/切歌/停止、迟到元数据隔离、有/无/纯文本歌词、慢或异常客户端、启停与退出清理、本地播放在飞牛失效后保持、最终包依赖及隔离升级。实际新功能的鼠标操作和系统媒体控制不能完全省略；打包前必须有可运行结果。

进度汇报按“当前批次 / 已完成项 / 阻断项 / 下一步”说明，以本清单计数，不堆叠旧通过数量。阶段完成或需要用户处理的实际阻断时通知；持续工作期间给出简短必要更新。允许在完整批次后形成本地提交，不擅自推送。

## 实现边界

- 快照由主窗口/播放器统一生成，使用真实播放时钟；拖动预览位置不能冒充已经完成的定位。媒体键沿用现有下一首优先队列、播放模式和定位取消保护。
- SMTC 事件转回 UI 线程，关闭自动命令处理后自行统一处理，避免重复切歌；时间轴使用适当刷新频率并在状态变化时立即更新，不机械沿用歌词刷新频率。参考 [Microsoft SMTC 文档](https://learn.microsoft.com/en-us/windows/apps/develop/media-playback/system-media-transport-controls)。
- 系统封面只传有界的本机字节/流，不传带认证的远程地址；迟到封面受曲目代次约束。
- 对外接口只读，限定当前 Windows 用户，设置明确开关；发现记录仅包含协议版本、随机实例标识和管道名。使用 [PipeOptions.CurrentUserOnly](https://learn.microsoft.com/en-us/dotnet/api/system.io.pipes.pipeoptions?view=net-10.0) 并验证权限与实例生命周期。
- 对外曲目标识为本实例的匿名标识；不输出访问令牌、服务器地址、完整文件路径、账号、来源内部 ID 或未脱敏异常。超量歌词明确返回限制状态或有界分页，不静默制造错误时间轴。
- 多客户端读取/订阅应有背压和大小限制；慢客户端不占用 UI 线程或阻塞音频。每个实例只移除自己创建的发现记录。
- 配置和发现文件使用现有 AppDataDirectory 规则，支持独立测试目录；歌词窗口位置恢复时纠正超出可用屏幕的坐标。保持用户已有配置及旧产物。
- 不混入当前用户对 bug、logo 文件的删除和 img/ 新文件；不清理已有私人测试配置，不复试此前被自动审查拒绝的操作。
