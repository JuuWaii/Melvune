# 随机访问输入的取消与超时

2026-10-01。处理 HttpRangeStream 在取消/关闭后的迟到数据和排队定位，不改变解码器配置、账户或远端数据。

## 修复

原先整块读取返回后直接写缓存、复制目标缓冲区并推进 Position，没有再次检查取消或关闭。受控正文在读取完成时触发调用者取消后仍返回数据，回归实际失败：读取被当作成功，位置和目标缓冲区改变。

现在在发布新块以及复制数据之前复核关闭状态与本次取消令牌；已经取消或关闭的结果丢弃，原位置和调用者缓冲区保持。取消单次读取不会关闭整个流，重新读取会重新请求未提交的块。

Seek 原先使用不可取消的 gate.Wait，关闭时可能仍等待一个迟到的读取退出。现在等待使用流生命周期令牌；关闭唤醒等待读取锁的定位，并以 ObjectDisposedException 结束，取得锁后再次检查关闭状态。关闭标记使用 volatile，跨线程的 CanRead/CanSeek 立即反映关闭。

## 验证

- 78 项基础检查通过。新增调用者取消后迟到完整块丢弃及重试、关闭后迟到块丢弃、读取未返回时关闭能够独立唤醒已阻塞定位三项受控回归；测试先确认定位线程实际等待，关闭后仍不释放正文，避免误把正文返回当作唤醒原因。
- 新增三个真实本机回环 TCP 场景：部分正文停滞时关闭，读取取消且服务端观察到连接关闭；正文达到生产的 15 秒超时后位置/目标数据保持、同一流可新连接重试；初次响应头停滞 15 秒后打开取消并关闭连接。临时端口只绑定回环地址，专用 HttpClient 不使用代理，不访问 NAS、不使用账号或用户音乐，结束后释放监听和连接。
- Release App 和独立 SeekProbe 构建零警告、零错误。更新后的生产输入/播放器在 MP3 Range 检查中通过前后定位、响应头/正文阻塞取消、切歌替换、调用者取消、活动定位停止和 60 次打开/连续定位/清理。
- 本轮受控原生打开取消耗时约 27 毫秒（响应头）和 3 毫秒（正文）。第 20/40/60 次私有内存分别约 78,716 / 93,736 / 76,176 KiB，末次比第 20 次减少约 2,456 KiB；这不是长期无泄漏保证，也不是真实 NAS 网络延迟。

真实 TCP 验证覆盖应用输入层的连接关闭与超时，不代替 NAS 断网、登录失效及窗口交互的完整矩阵。MP3 首次尾部定位仍读取约 4.46 MB / 4.80 MB；三个 VBR 起始恢复未达到内容探针目标，继续跟踪，见 SeekProbe README。
