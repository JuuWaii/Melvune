当前界面使用应用内部正在播放页与右侧覆盖队列，见 [UI 整合](UI_REORGANIZATION.md)。大封面的解码、缓存与最新验收见本文末尾；以下最初阶段记录保留当时的实现范围。

## 最初阶段范围（2026-09-23）

以 `img/ui示意图.png` 的左侧导航、内容区和全宽底部播放器分布为参考，使用 WinUI 3 原生控件与黑白主题资源。保留真实曲库入口，不填充虚构推荐内容。歌曲行展示缩略图、标题、歌手、专辑及时间；专辑列表展示封面；底部展示当前曲目封面与专辑。歌词在右侧展开。

默认读取 Windows 应用主题并监听变化；不修改系统设置。主题资源同时覆盖选择标记、音量/进度滑块和勾选控件。手动主题偏好、桌面歌词及更小窗口的进一步自适应仍在后续范围。

## 数据与行为

- 飞牛：歌曲/专辑 `coverId`，同源 GET `static/cover?coverId=…&size=256`；GET `lyric/list?trackGUID=…` 的 `list`、`preferred` 及各项 `content/guid/source/offset`。
- 歌词优先选择服务端指定版本，否则优先内嵌、同目录 LRC、手动来源中的有效时间轴版本，最后回退纯文本。支持多时间戳、毫秒、同时间翻译行合并、LRC offset 和服务端毫秒偏移。
- 本地：读取系统音乐元数据的专辑名；优先同名 JPG/PNG，再目录 `cover.jpg`、`cover.png`、`folder.jpg`，最后 Windows 音乐缩略图（内嵌封面）。歌词读取同名 `.lrc`，支持 UTF-8 和带 BOM 的 Unicode。
- 当前行随播放进度高亮并滚动，点击定时歌词调用现有播放器跳转。纯文本歌词不跳转。停止播放清空当前封面/歌词，切歌取消旧歌词和图片加载，旧会话封面不写回。
- 封面请求最多 4 个并发、15 秒上限、96 张内存缓存；单图最多 4 MiB，解码宽度 256。拒绝重定向与非图片响应，失败保留占位；不缓存凭据或将私有图片写入磁盘。
- 本地附属文件不跟随链接；歌词读取上限 512000 字节，时间轴上限 10000 项。超限/不支持编码显示加载失败，不影响播放。

## 2026-10-01：刷新后迟到封面隔离

音乐库刷新或重新关联会用相同来源 ID 注册新的扫描实例。此前旧实例已经开始的封面请求仍可能在缓存清空后完成，按相同键写入旧图片。现在本地封面写回前同时核对当前注册的实例引用；实例已替换或移除时丢弃结果，下一次请求从当前实例加载。此保护与现有曲目上下文、请求取消、飞牛会话检查一起执行。

窗口回归夹具在真实 PNG 解码后暂停写回，用同 ID 的新扫描实例替换来源，再释放旧请求；验证旧图片不会显示或入缓存，并验证新实例仍可加载有效封面。检查只操作生成的本地音乐库，不读取用户目录或修改 NAS。

最终 127 项窗口回归全部通过，报告阶段 complete、无失败；Debug/Release 构建零警告、零错误，隐私扫描通过。首次运行后续扫描取消检查的夹具仍比较替换前的对象，已改为以当前实例为基准，并重新运行完整回归确认。固定 preview.4 包尚未包含修复。

## 2026-10-01：歌词迟到结果与重试

歌词读取捕获本地来源实例或飞牛客户端；写回前再次检查当前实例及歌词能力。同 ID 的本地来源刷新、来源移除或歌词能力取消后，旧结果不能写回歌词列表。切换呈现曲目、停止和关闭仍通过请求取消保护新状态。旧来源失败也不会冒充当前来源的普通加载失败。

发生读取失败或来源变化后，歌词页面显示可重试状态。重新打开“歌词 / 正在播放”会从当前来源重新读取，保持已有音频流；来源仍不支持歌词时不发起读取。无歌词内容的正常结果仍显示“暂无歌词”，不进入失败重试循环。

## 2026-10-02：CR 换行与本地歌词矩阵

复现只有 CR 换行的定时/纯文本歌词被拼成一行：此前 Parse 删除全部 CR，导致多行时间戳共用合并后的文本，纯文本也失去分行。现在先将 CRLF 归一为 LF，再将独立 CR 转为 LF；支持三种换行及混合换行，既有时间戳、偏移方向和双语合并规则保持。

修复前新增回归在 CR 分支失败，证据 `.review-audit/lyric-newlines-before.log`；修复后 85 项基础检查通过。实际 `.lrc` 文件经过正式 LocalMusicSource 读取/解码/解析，覆盖 UTF-8 无 BOM/有 BOM、UTF-16 LE/BE BOM、UTF-32 LE/BE BOM、GB18030、GBK 八种编码 × CR/LF/CRLF 三种换行 × -200/0/150 毫秒偏移的 72 组定时歌词，另有 24 组纯文本，共 96 组。核对多时间戳、同时间翻译行、每个高亮边界前与边界处的查找，不将这些文字文件检查描述为新的音频编码验收。

## 2026-10-04：歌词页大封面与缓存收尾

列表、队列和底部播放器使用长边最多 256 像素的缩略图；正在播放页使用长边最多 1024 像素的大封面。两种尺寸分别缓存，来源身份继续包含在键中。歌词页未打开时不读取大封面，关闭时取消尚未完成的请求并释放隐藏图片控件的引用，再次打开可复用缓存。图片和歌词失败仍不影响音频播放。

先通过 Windows 图片解码器按比例缩放并应用 EXIF 方向，再把 BGRA 预乘透明度像素交给 WinUI `WriteableBitmap`。因此尺寸与缓存预算使用实际缩放后的像素，避免误把 `BitmapImage.PixelWidth` 返回的原图尺寸当作解码分辨率；超长竖图也限制长边，小图不放大。GIF 等多帧封面仅取静态首帧。缩放、方向及像素格式接口见 [BitmapDecoder.GetSoftwareBitmapAsync](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.imaging.bitmapdecoder.getsoftwarebitmapasync?view=winrt-26100)。

飞牛网页当前公开脚本的封面枚举为 160/600/1024/1600/2000；原有 256 参数没有列在该枚举中。客户端缩略图请求 600、大封面请求 1024，并在本机继续限制解码长边。接口只接受枚举档位，不提供不受限的原图请求，保留同源认证、拒绝重定向、图片类型与单响应 4 MiB 限制。公开脚本仅按文本核对，没有执行下载代码；依据文件为 `016b0624f32ee00e1e0de4c879cd3041-ChOD2xpy.js`，SHA-256 `e69b42ed8e40bd431a422f4670e902f47e95547b92fbd431623a2d72d18355e1`，保存在忽略目录 `.review-audit/cover-contract`。此接口结论只针对本次观察的服务端版本。

本地大封面优先取内嵌原图，再回退请求较大 Windows 缩略图；列表仍优先 Windows 缩略图，缺失时回退内嵌图。旁置封面的优先级、损坏/超限回退和无链接限制保持。内嵌读取仍使用受限的生产流解码器及三秒期限。

缓存满后按最近使用顺序逐张淘汰，最多 96 项且累计像素预算最多 48 MiB。预算不包括图片控件仍持有的引用、解码暂存、对象开销或显存，不是进程总内存上限。并发最多四个、单次请求十五秒、来源实例/会话及能力变更后的迟到结果隔离保持。

同一图片控件、呈现对象及当前来源的重复加载共用待完成任务，避免 `Loaded`、数据上下文变化和主动打开歌词页相互取消。控件卸载、来源变化或关闭页面仍取消原请求。复测还发现右键菜单主题切换后要等退出动画才清空菜单状态，现改为主题事件发生时立即清理当前菜单；旧菜单的关闭回调不能清理后来的菜单。

封面专项入口为 Debug 参数 `--preview-synthetic --verify-artwork-window`；实际合成窗口加入 `--preview-playlists --preview-artwork --preview-dark`，只生成隔离 WAV、LRC 与纯色 PNG，不改用户音乐目录或 NAS。完整窗口入口和只读 NAS 探针沿用上文参数。
