## 窗口尺寸被“所有音乐”重置：已修复

原因是 Debug 合成模式的导航重新调用初始化预览方法，从而再次执行 `--preview-compact` 的尺寸和主题设置。现在只有初次打开预览时应用这些参数，导航走正常歌曲浏览路径，也不再重复设置静音。实际验证最大化后点击所有音乐仍保持最大化；窗口回归覆盖调整到 980×780 后再导航，尺寸不变。

## 跳转加载慢：首阶段优化，继续保留追踪

原来的 FFmpeg stdin 输入不可随机定位，输出端 `-ss` 每次从头解码并丢弃目标时间之前的音频。仅缓存压缩文件不能消除这部分重复解码。

现在对已知时长不超过 8 分钟的曲目使用后台 PCM 预读：不等待整首完成便开始播放，已解码位置直接从内存取样，跳转不重启 FFmpeg。缓存按需增长，单曲上限 96 MiB，不落盘；暂停时预读仍可继续，因而会提前读取网络音频。停止/切歌取消读取并释放缓存。元数据错误导致实际音频超过上限时回退原解码链路，避免无限增长。

这解决的是缓存覆盖位置的重复跳转。超长曲目、第一次跳到尚未下载的位置和慢网络仍可能等待，不能标为全部解决。下一阶段需实现可随机访问的解码输入，并验证取消、远端 Range 与鉴权隔离；不会把完整 URL/Cookie 交给 FFmpeg。

## 标题栏色差：已修复

原生 AppWindow 标题栏的激活/未激活背景与按钮背景按应用浅深主题更新，文字保持对比度，保留系统最小化/最大化/关闭行为。已实际检查深色窗口，窗口断言覆盖两种主题的标题栏颜色。参考截图只用于外观确认，没有纳入版本库。

## 后续顺序

后续缓存修复：预读数据原先积满 64 KiB 才发布，在输入分段缓慢时会让已到达的音频继续等待。现改为每次读取后发布可用字节，仍按固定块保存以支持定位。释放操作幂等，立即唤醒等待者并在后台读取退出后清空缓存、释放取消资源；取消一次定位读取不会取消整个缓存。受控慢输入回归已验证部分数据可立即读取、取消隔离、停止唤醒、重复释放及输入所有权。57 项基础检查及 Release 构建通过；这不代表真实慢网或长音频随机跳转已全面解决。

1. P0：按 [通用跳转方案](SEEK_ARCHITECTURE.md) 优先验证 FFmpegInteropX 随机访问流接入；随后验证长音频跳转、慢网络取消及真实 NAS 连续拖动性能，覆盖缓存上限回退和频繁切歌内存曲线。
2. P0：整理下一份可验证版本，集中回归这三项反馈、封面、歌词、主题及本地播放。
3. P1：封面/歌词失败重试与加载状态、歌词偏移/编码矩阵、手动主题偏好。
4. P1：多库分类与跨库本地歌单，随后飞牛同步歌单。
5. P1/P2：非 UI 设置同步、第三方音乐源、对外媒体信息；桌面歌词保持后续。

现有产品路线图的长期需求继续保留，本队列优先处理用户反馈和当前版本可验证性。
