# 通用 Subsonic 兼容源与第三方连接修复

日期：2026-10-14。本批接入通用 Subsonic 只读音乐源，保留 Navidrome、Emby、本地与飞牛来源。音乐库管理新增动态来源选项，所有音乐提供独立筛选；共用播放、封面、混合本地歌单与关闭后续播。服务端收藏和歌单写入不在本批范围。

通用源通过 `ping` 验证认证，使用 `getAlbumList2`（按名称分页）和 `getAlbum` 获取专辑内曲目。空 `search3` 并不保证返回完整目录，既有 Navidrome 的已验证路径保持，通用源选择标准目录接口。未归入专辑的歌曲、缺少所需接口的服务器不在首版保证范围。搜索在已完整加载目录内按曲名、歌手、专辑匹配；读取中失败不提交半份目录，最大 10000 首。

原始音频使用 `stream` 的 `format=raw`，要求服务支持 HTTP Range；封面按服务返回的标识读取。结构化歌词仅尝试 `getLyricsBySongId` 扩展，不支持时交给解码器尝试音频内嵌歌词，不按同名歌曲模糊匹配。非认证的歌词服务错误也尝试已解码的内嵌歌词；没有内嵌内容仍保留失败和重试提示，认证与取消不吞掉。

连接持久化复用加密 Subsonic 凭据存储，旧记录没有 `Provider` 时仍视为 Navidrome，UUID 和凭据不迁移。新的类型字段只接受 `navidrome` / `subsonic`；编辑保留服务、账号及类型身份，变更需新建音乐库，避免旧歌单引用指向另一账号。密码只用于生成带盐认证摘要，摘要与盐使用当前 Windows 用户 DPAPI 加密；协议需要携带认证参数，因此使用最终服务地址并拒绝重定向。更换 Windows 用户需重新输入凭据。

Navidrome 保存和删除以原子索引替换为提交点；提交后的内存连接直接镜像已知结果，无二次索引读取。应用关闭时不再更新 UI。第三方管理页保存/删除成功后直接更新卡片，可见目录刷新失败单独提示刷新，不将已提交操作误报为失败。复用旧凭据前拒绝跨账号、服务或类型的编辑。

实现依据：[Subsonic 官方 API](https://www.subsonic.org/pages/api.jsp)、[OpenSubsonic stream](https://opensubsonic.netlify.app/docs/endpoints/stream/)、[结构化歌词扩展](https://opensubsonic.netlify.app/docs/endpoints/getlyricsbysongid/)。官方 API 页面直接读取成功，检索工具限流不影响此次协议核对。

集中验证：应用及测试 Debug 构建零警告、零错误；Navidrome/Subsonic 协议与存储八组、Emby 协议与存储十组、续播存储专项通过。实际 WinUI 受控协议窗口 45 项、Navidrome 20 项、Emby 25 项、桌面/音频输出/主题 152 项，以及续播六个独立进程 68 项，总计 310 项通过。通用与 Emby 的单击播放首个 Playing 事件均从保存的 15 秒开始。窗口报告在 `.review-audit/subsonic-20261014/`，全部使用独立配置和合成音频，不写入真实账号或音乐服务。

专项包含专辑分页与重复、缺失曲目/count 不一致及数量上限拒绝，旧记录无 Provider 兼容、DPAPI 重建与账号类型隔离，真实动态编辑/确认删除、跨源同歌曲 ID、混合歌单、普通服务失败保留目录、认证撤销隔离、续播及歌词 503/401/无内嵌内容。提交后故障用临时损坏独立测试索引并取消调用 token 验证，完成后恢复提交后的字节；保存/删除真实管理页仍正确显示成功。

首轮 Emby 窗口夹具仍按旧四项数量断言，已更新为五项后通过；既有核心元数据夹具复合断言曾失败，调查发现并行请求计数使用非原子自增，改为 Interlocked 并增加诊断，相关生产同步器未变更。修正后完整核心回归 120/120 通过。交付哈希另补充。

真实 Subsonic/Navidrome/Emby 服务版本、代理、权限及实际听音仍待环境验收。受控窗口为实际 WinUI/解码器与 DPAPI 执行，部分内嵌歌词错误回退使用解码结果 TCS 夹具，不据此宣称新增真实文件格式支持；最终 Release 键鼠操作单独待验收。任意 JSON 映射、非标准鉴权、转码、完整队列与新完整安装器后置。
