# MP3 定位预滚修复

2026-10-01。源码构建及有限合成音频回归阶段完成，固定 preview.6 包不被覆盖。本轮仍未完成网络读取量、真实慢网、全部编码变体和听音验收。

## 实现与构建

固定 FFmpegInteropX 的源代码提交为 `841fc8e79346a235906f1dbd45be53034b2e2f52`，与 Desktop.Lib 2.1.0 的 NuGet 元数据一致。`native/decoder/mp3-preroll.patch` 只修改纯音频 MP3 的定位：解码位置提前 500 毫秒，最早为曲首；缓冲定位也查找这段更早的输入，不足时回到正常定位。交给 MediaStreamSource 的实际起始位置保持用户请求的时间，使解码器恢复状态而不改变曲目时间线。其他格式及视频定位沿用原行为。正式配置继续不启用 `fflags=+fastseek`。

`scripts/build-native-decoder.py` 从固定提交应用补丁，使用 `native/decoder/toolchain-lock.json` 固定微软 MSVC 14.44、Windows SDK 26100、C++/WinRT 和原项目的 Windows App SDK 1.4 构建依赖。所有下载校验 SHA-256，普通工作副本解压到 `.tools/native-decoder`；NAS工作副本使用本机临时工具链缓存并将最终输出写回NAS，不运行 Visual Studio 安装器、不修改系统 PATH。构建要求 Python 3.11+、Git 和已还原的项目 NuGet 包。C# 投影、WinMD 及 FFmpeg 8.1.2 动态库保持原锁定版本；桥接 DLL 文件版本为 `2.1.0.1`。

常规 `scripts/native.ps1 build` 和 `scripts/package-preview.ps1` 会在缺失或输入变化时构建补丁库，缓存有效时直接复用。直接调用 dotnet build 前，先还原并运行：

```powershell
python scripts/build-native-decoder.py
```

`native/Directory.Build.targets` 在 App 和 SeekProbe 构建前核对补丁、构建脚本、依赖锁和 DLL 哈希，并在 Build/Publish 输出中复制补丁 DLL 及 `native-decoder-build.json`。旧库或输入变化会明确失败，不静默回到 NuGet 原版库。生成目录和预览包带有实际 DLL 哈希及源代码、补丁和构建依赖标识；NuGet 锁文件的原版 DLL 哈希不能用来证明补丁库身份。打包另外保留补丁和构建材料以及 Apache 2.0 许可。

## 2026-10-03 采样率与双声道内容矩阵

内容探针增加 44.1/48 kHz 和单/双声道布局，双声道使用两份不同的确定性噪声，独立顺序解码参考保持通道数；实际 PCM 逐通道比对，每个通道均要求 50 毫秒内恢复、至少两帧且全部后续帧保持相关度大于 0.8、时间误差不超过 50 毫秒。输出布局不匹配直接失败；没有通过混合或只取左通道降低检查范围。默认原矩阵仍为 48 kHz 单声道，非默认布局使用独立报告名。

四种布局各验证 WAV、FLAC、128 kbps CBR MP3、q=2 VBR MP3、q=4 OGG 的四处定位，共 80/80 通过。实际加载补丁 DLL 哈希仍为 `3DBE6C7083A78C8129BD994C5499385098645235A5E0B23B5F0E6E7C1585B803`。报告位于 `.review-audit/content-layout-probe/seek-content-verification*.json`，逐帧包含通道索引，错误字段为空；各通道的已知位置和偏移 20 秒的反向控制也执行通过。

本轮是准确模式、受控 HTTP Range 和生成音频，不等于所有采样率/声道、编码参数、实际听音或真实连续鼠标拖动均验收。MP3 首次远端定位的大读取量仍存在；快速模式继续不进入默认配置。
